# 09 GB/T 39362—2020 党政机关电子公文归档规范

## 一、标准名片

| 项目 | 内容 |
| --- | --- |
| 发布/实施 | 2020-11-19 发布，**2021-06-01 实施** |
| 归口 | **国家密码管理局**归口（注意：不是国家档案局） |
| 起草 | 国家档案局、上海中信信息发展股份有限公司 |
| 适用范围 | 各级党政机关**电子公文系统**产生的电子公文的归档和处理；其他机关和企事业单位可参照执行 |

## 二、核心术语（第 3 章）

| 术语 | 定义 |
| --- | --- |
| 电子公文 | 以数字形式存储于磁盘、光盘等媒体，依赖计算机系统阅读、处理并可在通信网络上传输的公文 |
| 电子档案 | 具有凭证、查考和保存价值并**归档保存的电子公文及相关信息** |
| 归档 | 将具有保存价值且**办理完毕**的电子公文及相关信息经收集、整理并向档案部门移交的过程 |
| 数字对象 | 通过计算机呈现的对象（如系统/软件生成的文件） |
| 内容数据 | 电子公文或电子档案中包含的数字对象 |
| 开放式版式文档（OFD） | **独立于软件、硬件、操作系统、输出设备**的版式文档格式（GB/T 33190） |
| 信息包 | 由内容数据和相关保存描述信息构成的信息整体 |
| 归档信息包 | 形成或办理部门归档时组织并向档案部门提交的信息包 |
| 封装 | 将电子公文/电子档案及其元数据作为整体按指定结构打包 |
| 数字对象标识 | 一份电子档案中**每个文件**的编号 |

## 三、总则（第 5 章）——重点原则

- **归档三原则**：保留形成原貌、保持有机联系、保证长期可用。
- 发生责权交接、数据格式转变等**重大变化**时应形成并留存**变化记录**。
- **归档信息包中不包含非开放的压缩、加密、签名、印章、时间戳等技术措施**（减少技术依赖性）。
- 分工：收集、整理、移交由**形成或办理部门**完成；档案部门负责**接收**并对全过程业务指导。
- 归档时机：宜**随办随归**；向档案部门移交时间**最迟不超过电子公文整理完成后的次年 6 月**。
- 归档范围和保管期限表：依据《机关文件材料归档范围和文书档案保管期限规定》（国家档案局令第 8 号）制定。

## 四、归档流程（第 6 章）——4 环节 12 步骤（必背）

| 环节 | 步骤 |
| --- | --- |
| ① 文件收集 | 捕获 → 录入 → 转换 |
| ② 文件整理 | 组件 → 编号 → 封装 |
| ③ 文件移交 | 移交检测 → 移交登记 → 提交 |
| ④ 档案接收 | 接收检测 → 接收登记 → 接收确认 |

### 各步骤要点
- **捕获**：形成和办理过程中随时捕获；**元数据与内容数据一起捕获**；保持有机联系和原貌。
- **录入**：针对未进系统流转的文件——扫描并著录元数据、上传挂接、脱机数据包导入。
- **转换**：不符合归档格式要求的进行格式转换。
- **组件**：一般**以件为单位**整理，件内构成及排序符合 DA/T 22。
- **编号**：按 DA/T 22 分类排序并**编制档号**。
- **封装**：将电子公文及元数据封装成**归档信息包**。
- **移交检测**：按 **DA/T 70—2018** 对**真实性、完整性、可用性、安全性**检测，合格后方可提交。
- **移交登记**：清点核实文种、成文日期、保管期限、件数、大小，登记《电子文件归档登记表》（GB/T 18894 表 A.1）。
- **提交**：归档信息包连同登记表一起提交。
- **接收检测**：档案部门对信息包四性检测，**不符合要求的退回**。
- **接收确认**：接收符合要求的信息包并确认，归档流程结束。

## 六、归档数据组织（第 8 章）

### 归档信息包结构（示例）
根目录：
- 说明文件.XML（信息包标识、类型、创建者、创建时间、创建环境、存储位置、说明）
- 年度文件夹 → 保管期限文件夹 → 机构文件夹 → **电子档案文件夹**
  - 电子档案元数据.XML
  - 电子档案内容数据 1.OFD、2.MP4、3.SVG、…n.WAV

### 文件命名与内容
- **电子档案文件夹以档号命名**（如 Z109-WS·2011-Y-BGS-0001）。
- 内容数据命名：**"档号" + "-" + 两位件内顺序号**（如 …0001-01.OFD）。
- **OFD 文件是内容数据主体**：包括文件处理单和公文主体（正本、定稿及历次修改稿），可多个或合并为一个。
- 无法转 OFD 的图形、音视频等按第 9 章格式要求置于文件夹中。
- 元数据以 **XML** 存放：多 OFD 时独立存在；单 OFD 时可**嵌入 OFD 文件**中。

## 七、归档格式要求（第 9 章 + 附录 E）——OFD 为核心

| 文件构成 | 形态 | 归档格式 |
| --- | --- | --- |
| 文件处理单 | 纸质（扫描） | **双层 OFD** |
| | 电子（网页、文本） | OFD |
| 公文主体（含正本、定稿、历次修改稿） | 纸质（扫描） | **双层 OFD** |
| | 电子（文本） | OFD |
| 其他附属文件 | 文本类 | OFD |
| | 图像类 | JPG、TIF |
| | 图形类 | SVG、STEP |
| | 音频类 | WAV、MP3 |
| | 视频类 | AVI、MP4、MPG |
| | 社交媒体类 | HTML、MHT |

### 单 OFD 电子档案三层次（附录 E，必背）
1. **形式层**：图像/版式格式，保持原件真实性，用于调阅显示；
2. **内容层**：文本格式，抽取内容用于**全文检索**；
3. **元数据层**：XML 格式，封装元数据，使 OFD 作为完整电子档案**不依赖文件系统、数据库独立存在**。

> 件内文件排序：**正本在最上面，依次为文件处理单、定稿、历次修改稿**；扫描图像经 **OCR** 生成**双层 OFD**。

## 八、系统功能要求（附录 A）——记忆要点

- 总体：覆盖四环节；设立**独立预归档库**；支持内置式/独立式对接；**三权分立**权限控制模型；支持**国产操作系统、数据库、中间件**。
- 捕获：自动捕获内容数据及元数据；不符合规范记录错误日志。
- 录入：扫描著录、上传挂接、脱机导入；设置**只读属性杜绝非法修改**。
- 转换：文本/图像转 OFD 做到**所见即所得**；扫描图像自动 **OCR 转双层 OFD**；支持多 OFD 合并及 XML 嵌入/提取。
- 编号：按分类方案和排列顺序编档号；支持**归档章自动生成**。
- 封装：内置信息包结构；支持公开压缩算法打包；封装后自动生成**校验信息或数字摘要**（校验算法 CRC16/CRC32；摘要算法 SM3、MD5、SHA-1、SHA-256）。
- 移交/接收检测：检测项目包括四性，符合 DA/T 70—2018。
- 接收确认：解包入库；检测不通过**退回**。

## 九、归档接口（附录 B）

- 两种方式：**推送**（电子公文系统发起，putArchivingDocuments）和**捕获**（电子档案管理系统发起，getArchivingDocuments）。
- 数据交换采用**信息包**方式，接口宜采用 **Web Service** 服务调用实现。

## 十、映射关系（附录 D）

- 与 **GB/T 33480—2016**（党政机关电子公文元数据规范）对应各元素；
