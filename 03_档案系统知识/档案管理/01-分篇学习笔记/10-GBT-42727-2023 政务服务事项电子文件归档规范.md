# 10 GB/T 42727—2023 政务服务事项电子文件归档规范

## 一、标准名片

| 项目 | 内容 |
| --- | --- |
| 发布/实施 | 2023-05-23 发布，**2023-12-01 实施** |
| 归口 | 国家档案局提出并归口 |
| 起草 | 浙江省档案局、浙江省档案馆、福建南威软件有限公司 |
| 适用范围 | **政务服务事项办理系统**中形成的依申请办理的行政权力事项和公共服务事项电子文件的归档；行政处罚、行政检查等**参照使用** |

## 二、核心术语（第 3 章）

| 术语 | 定义要点 |
| --- | --- |
| 政务服务事项 | 政府部门及其授权或委托的其他组织行使依申请办理的行政权力和公共服务事项过程中提供的服务事项 |
| 办件 | 政务服务事项按程序办理完毕并形成相应结果的**单个活动**，是办理和归档的**基本单位** |
| 容缺归档 | 某些归档材料办理过程中未进入办理系统，归档时以**不完整状态归档并标记**的方式 |
| 归档信息包 | 实施机构按档案管理要求组织并提交的信息包 |
| 电子文件号 | 系统按规则赋予归档政务服务事项电子文件信息整体的**唯一编号** |

## 三、总体原则和要求（第 4 章）

- 归档要求：符合**来源可靠、程序规范、要素合规**。
- **三类部门职责（注意与 18894 的四类不同）**：
  | 部门 | 职责 |
  | --- | --- |
  | 业务办理部门 | 收集、整理、移交归档 |
  | 档案部门 | 制定归档范围和保管期限表、提归档功能要求、接收保管利用 |
  | 信息化部门 | 建设归档功能、参与系统建设、信息化支持 |
- **归档时间**：宜**在线归档**；最迟不超过政务服务事项**办结后的第 2 年 6 月**。
- 系统重大调整：宜在完成系统内电子文件归档工作后实施。
- 归档范围：参照纸质文件归档范围与保管期限；**证据性材料、程序性材料、结果性材料**应纳入归档范围；保管期限应**不低于行政管理、诉讼、审计等活动所需的追溯年限**。
- 系统安全：按**国家网络安全等级保护**标准建设，采用电子认证、密码应用等可靠技术保障。

## 四、归档功能要求（第 5 章）

六大功能：**归档配置、整理组件、清点检测、归档信息包封装、数据交换、统计和审计**。
- 归档配置：以政务服务事项**最小细分项**为单位配置归档材料目录；支持电子文件号命名规则、密级配置；支持**版本管理**和在线审查。
- 整理组件：自动收集整理；人工补录；无法补充的**容缺标记并备注原因**。
- 清点检测：完整性、规范性清点 + 信息包四性检测验证。
- 封装：组件 + 元数据 XML 封装；可加**可信时间戳、数字摘要**。
- 统计审计：操作及操作人员、时间、结果日志记录、跟踪、审计。

## 五、归档流程（第 6 章）——两阶段

### 预归档阶段（业务办理部门）
文件收集 → 整理 → 清点 → 形成归档信息包 → 生成验证信息 → 归档检测 → 数据交换

### 正式归档阶段（档案部门）
接收检测 → 登记编目 → 入库

### 各步要点
- **收集**：办结后自动采集组件及元数据；以数据共享形式从外部调用的**电子证照及其元数据一并采集**。
- **整理**：**以办件为单位**，以文件夹规范组织存储，按规则生成**电子文件号**命名。
- **清点**：门类、保管期限、件数与归档材料信息**匹配**；缺失的补充后重新整理；无法补充的记录原因后**容缺归档**。
- **验证信息**：可信时间戳、数字摘要；**单独保存并与归档信息包关联**。
- **归档检测**：参考 DA/T 70，四性检测，记录检测时间、结果。
- **数据交换**：从办理系统交换到电子档案管理系统，生成**数据交换目录**作为凭据。
- **接收检测**：不合格**退回并注明原因**。
- **登记编目**：导入预归档库登记，按 **DA/T 13** 自动编档号（全宗号、门类代码、机构（问题）代码等）；**不应修改组件和办理阶段元数据的原始内容**。
- **入库**：导入正式库管理。
- **变更补正**：已归档文件需变更/补正组件及元数据时，采用**嵌套结构**形成新的归档信息包，再次归档**替代原包**。

## 六、归档信息包的内容、结构与命名（第 7 章）

### 内容
- **一个办件 = 一个归档信息包**；以 **ZIP** 格式存储，编码 **UTF-8**。
- 内容：电子文件组件 + 三类元数据。

### 三类元数据（重点）
| 类别 | 文件命名 | 元素范围 | 内容 |
| --- | --- | --- | --- |
| 归档配置信息 | 归档配置信息.XML | A1～A26 | 归档材料目录、容缺归档情况、实际采集组件信息（用于清点和完整性检测） |
| 办件基本信息 | 办件基本信息.XML | B1～B40 | 行政相对人、办理部门、办理事项、结果等信息 |
| 办理流程信息 | 办理流程信息.XML | C1～C8 | 环节、人员、意见等流程信息（环节名称、经办部门、经办人、意见类型、意见内容、办理时间） |

### 结构
- **一般结构**：以电子文件号命名的归档文件夹；组件按**归档材料目录**（序号+名称）存放于对应文件夹。
- **嵌套结构**：变更/补正时，在归档文件夹内放原始信息包 + 补正后的组件和元数据。

### 电子文件号命名规则（必背）
`业务办理项编码 - 年度 - 保管期限 - 归档流水号`
- 业务办理项编码（33 位）= **18 位统一社会信用代码 + 1 位行使层级代码 + 12 位基本目录编码 + 2 位业务项代码**；
- 年度：4 位办结年度；
- 保管期限：定期用 "D+时限"（如 **D30**），永久用 **"Y"**；
- 归档流水号：8 位数字，每年从 00000001 起，按同一业务办理项编码顺序编码。

## 七、存储格式要求（第 9 章）

- 一般要求：以办理系统形成时**原采用且符合标准的格式**为准；应能**脱离办理系统**正确读取使用。
- 附件（文档、音频、视频）：符合国家/国际标准的文件格式，按 GB/T 18894 执行。
- **数据链接形式**存放的：应**下载并保存**。
- **关系数据库临时抽取组合**显示的：转换 **OFD、XML** 等格式；有标准文本样式的按标准样式转 OFD。
- **电子证照**：按 **GB/T 36905—2018** 以版式电子文件形态归档；查证信息参照电子出证规范归档。
- 难以人工读取的元数据文档：同时保存**结构说明文档**或以注释说明。

## 八、数据交换要求（第 10 章）

- 批量交换时对同一批次归档信息包建立 **XML 数据交换目录**，随包传输。
- 命名：`数据交换目录-(系统标识)-(批次号).XML`，编码 UTF-8。
- 要素：系统标识、批次号、交换日期、交换数量、交换目录信息（含电子文件号、办件名称、归档时间、部门编码、部门名称）。

## 九、必背数字速记

| 要点 | 内容 |
| --- | --- |
| 1 个基本单位 | 办件 = 归档基本单位 = 一个归档信息包 |
| 2 个阶段 | 预归档（业务部门）、正式归档（档案部门） |
| 3 类元数据 | 归档配置信息（A）、办件基本信息（B）、办理流程信息（C） |
| 3 类材料 | 证据性、程序性、结果性材料 |
| 3 类部门 | 业务办理、档案、信息化 |
| 2 年 6 月 | 归档最迟时限（办结后） |
| 33 位编码 | 18 信用代码 + 1 行使层级 + 12 基本目录 + 2 业务项 |
| D30 / Y | 定期 30 年用 D30，永久用 Y |
| 1 种特殊归档 | 容缺归档（标记 + 原因说明） |
| 嵌套结构 | 变更补正时替代原归档信息包 |
